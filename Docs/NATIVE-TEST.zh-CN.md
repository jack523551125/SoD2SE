# Rust 版实机测试

当前是候选版。离线检查已运行；存档、玩法、MO2 和输入设备的实际结果由测试者记录。Xbox 蓝牙手柄属于本次测试设备。

## 准备和启动

`Automation/NativeTest.py prepare` 使用显式指定的游戏、存档和解压包路径。它先校验游戏版本与包哈希，复制并校验存档备份，再按已审查的旧版文件清单迁移安装。备份、配置、资源和报告都留在本地。此命令不会启动游戏或切换正在运行的 MO2 实例。

当前本机按用户要求使用 `E:\Game\SD2_mod` 的 MO2 配置档 `SoD2SE Rust Test`。MCM 已内置于框架；无限随从与验收示例由 MO2 虚拟映射；只有框架安装在游戏根目录。打开桌面 `SoD2SE Rust 测试` 的 MO2 入口，选择该配置档并运行 `SoD2SE (MO2)`。不要使用含旧版 managed Mod 的 Default 配置档测试 Rust 框架。

测试包包括可选的开发验收示例：一个布尔值和一个 1–10 的整数，只验证配置、翻译和风险标记，不改变玩法。正式的无限随从没有新增数量滑块。

## 首轮：MCM 和无限随从

1. 进入主菜单，打开设置，找到 Mod 设置入口。应显示 MCM、无限随从和开发验收示例。
2. 用键盘修改示例开关与整数，连续保存两次；关闭、重开页面，检查值是否保留。整数不可超出 1–10，实验性标记应可见。
3. 切换 Xbox 蓝牙手柄，测试方向、确认、返回、页面关闭后焦点恢复。测试中断蓝牙后重连，以及键盘和手柄来回切换。
4. 载入已有测试社区，通过原版交互招募多个随从，记录实际人数及任务、关系、重复招募条件是否异常。不要将失败原因猜测为数量限制。
5. 保存并退出，再从同一入口启动，检查社区和配置是否正常载入。
6. 游戏运行时，用 `NativeTest.py report --environment <测试目录>` 导出诊断。诊断连通 PASS 不代表上述人工步骤通过。

## 无 MCM 路径

退出游戏和 Loader，运行 `NativeTest.py mode --environment <测试目录> --mode without-mcm`。再次启动，确认无限随从可工作；Mod 设置前端不应启用。可通过 Developer Tools 的 Registry 接口修改示例配置。测试完退出，再用 `--mode with-mcm` 恢复前端。

## 更新、回退与卸载

新候选版本先通过框架 `install` 完成带备份的更新；Mod 包必须匹配新框架精确 revision，并在游戏退出后更新。原生代码更新必须重启。

`NativeTest.py rollback --environment <测试目录>` 校验本次文件所有权、恢复受控 UI 覆盖、卸载框架并恢复旧版文件。遇到用户修改或外来文件时拒绝覆盖。存档不会自动还原，测试前的副本始终保留；需要恢复时先保留测试后的存档副本。游戏退出后的原版存档载入、超出原版限制的随从状态仍需要实际验证。

MO2 测试使用独立的便携程序副本与 `SoD2SE Rust Test` 配置档，只启用本次 Rust Mod。退出游戏后先运行 `NativeTest.py mode --environment <测试目录> --mode mo2`，将实体测试插件移回备份目录，避免与 MO2 虚拟映射重叠。然后打开测试 MO2，运行 `SoD2SE Rust Test`。原有 MO2 实例与 Default 配置档保持原样；存档仍共享本机测试社区，并有已校验备份。此测试需要分别记录 USVFS、实际子进程、配置档切换和禁用 Mod 的结果。独立启动测试不能替代 MO2 验收。回到独立启动测试前退出 MO2 与游戏，运行 `--mode with-mcm` 恢复实体测试插件。

## 反馈

记录入口、版本、社区槽位、操作步骤、预期与实际结果、输入设备和诊断报告。不要上传原始存档、派生游戏资源、session.json 或内存转储。手工未执行的项目保留 NOT_RUN，失败项记录 FAIL。

当前合并包不再启用独立 Rust MCM Mod，避免同 ID 重复加载。配置由 Registry 写入 Plugins 命名空间，MO2 对应 overwrite/Root/Plugins/SoD2SE/Settings/<配置档 ID>/registry.json。
