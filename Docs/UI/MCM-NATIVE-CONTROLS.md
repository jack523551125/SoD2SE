# MCM original-control host

MCM menu entries in main_menu and pause request the game's normal settings-layer lifecycle. A one-use request selects a dedicated Mod view inside that native host. Ordinary Settings continues to show original categories. This reuses the verified controls and original modal/input/hint ownership; it does not claim a separately created Iggy player or arbitrary custom-page support.

The framework owns all three reviewed resource overlays: pause and main_menu entry points, plus settings as the native control host. Mods register metadata through Settings Registry and never distribute a replacement settings.uasset. MO2 refuses conflicting resource paths, validates originals/derived hashes and stages each receipt into an independent cache generation.

## Interaction

Native category buttons form the scrollable Mod sidebar, followed by Refresh and Close. The current Mod has the original highlight; native button_set handles focus. Settings use original toggle and numeric slider/value controls with separate in-memory setting_list objects per parameter. They never bind the game's real setting_list or its gameplay-setting submit callbacks.

Keyboard/controller selection and adjustment follow the original settings protocol and hint bar. Back moves from controls to the Mod list, then closes through the native host; dialogs cancel first. The last valid Mod survives reopening. Details provide wrapped text with mouse-wheel scrolling and a focusable details action for keyboard/controller scrolling. Mods without parameters show their status and description.

Numeric dragging previews locally and submits on release; keyboard changes and toggles submit immediately. Registry remains the sole validator and persistent store. Saving disables duplicate edits; completion refreshes committed values without recreating controls. Failed writes restore committed values. Restart markers remain distinct from save confirmation.

Dangerous changes use the existing revision-bound consent protocol and original native action buttons, initially focused on Cancel. Defaults reuse the same write path. The existing v2 model, setting IDs and plugin C ABI 1 are unchanged.

## Internal routing extension

The fixed four-integer `SoD2SE_Mcm_v2` protocol adds operations 29 (request native Mod view) and 30 (consume the request). Their other three arguments must be zero. The handoff expires after 10 seconds and is consumed exactly once. Legacy v1 rejects these operations. There is no public address-access or general native-call facility.

Resources are generated by reviewed ReverseEngineering tooling. Raw game inputs and derived assets remain local; only reviewed metadata is archived. The joint E01/E02 experiment was reported passed by the owner on 2026-10-05; that does not constitute acceptance of this new Registry-integrated MCM.

## Acceptance

The new MCM must be tested from both menu entries for language consistency, mouse/keyboard/Xbox input, scrolling, focus return, ordinary settings isolation, save feedback, defaults, dangerous consent and repeated open/close. Offline checks establish build and contract validity; game behavior remains pending owner acceptance.
